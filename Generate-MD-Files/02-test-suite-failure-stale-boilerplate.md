# Issue 2: Test suite fails — stale CRA boilerplate assertion

**Severity:** High (fails CI test step)
**Status:** Fixed
**File:** [src/App.test.js](../src/App.test.js)

## Symptom

`CI=true npx react-scripts test --watchAll=false` fails:

```
Test Suites: 1 failed, 1 total
Tests:       1 failed, 1 total

  ● renders learn react link

    Unable to find an element with the text: /learn react/i.

      6 |   const linkElement = screen.getByText(/learn react/i);
        |                            ^
```

## Root Cause Analysis

`App.test.js` is the untouched default test generated by `create-react-app`:

```js
test('renders learn react link', () => {
  render(<App />);
  const linkElement = screen.getByText(/learn react/i);
  expect(linkElement).toBeInTheDocument();
});
```

It asserts on the "Learn React" link from CRA's starter `<App>` markup. That markup was fully replaced by the real app UI (`Header`, `JsonEditor`, `ActionBar`, `OutputViewer`) — no "learn react" text exists anywhere in the current component tree — so the query returns nothing and the test throws.

This is the single test in the project (`src/App.test.js` is the only `*.test.*` file in `src/`), so the whole test suite is currently red. Any CI pipeline that gates on `npm test` will fail here, independent of the Issue #1 build fix.

## Solution

Replace the stale assertion with a test that reflects actual app behavior. Two options, from minimal to more valuable:

**Minimal (unblock CI):**
```js
import { render, screen } from '@testing-library/react';
import App from './App';

test('renders the app header', () => {
  render(<App />);
  expect(screen.getByText(/JSON Formatter & Compare Tool/i)).toBeInTheDocument();
});
```

**More valuable (covers the core feature):** add a test that types invalid/valid JSON into the input and asserts the formatted output or error message appears. Note `@monaco-editor/react`'s `Editor` won't render fully in jsdom — mock it with a lightweight `<textarea>` stand-in that calls `onChange`, per the guidance already captured in [.claude/agents/react-testing.md](../.claude/agents/react-testing.md).

## Recommendation

Delegate this to the `react-testing` subagent — it already carries the project-specific conventions (RTL query style, Monaco mocking approach, `CI=true` verification step) needed to do this correctly rather than just patching the one failing assertion.

## Applied fix

Implemented the "more valuable" option. `src/App.test.js` now:

- Mocks `@monaco-editor/react`'s `Editor` with a `<textarea>` stand-in that preserves the `value`/`onChange` contract, distinguishing the read-only output editor via `options.readOnly`.
- Asserts the header renders (`JSON Formatter & Compare Tool`), replacing the stale "learn react" check.
- Types valid JSON into the mocked input editor and asserts the formatted result appears in the output editor.
- Types invalid JSON and asserts the `Invalid JSON` error message appears.

**Verification:** `CI=true npx react-scripts test --watchAll=false` → `Test Suites: 1 passed, 1 total`, `Tests: 3 passed, 3 total`.
